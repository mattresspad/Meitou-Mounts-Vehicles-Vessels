# Meitou integration notes from the transport playtest

MeitouClient **v0.17.4, API 2, Windows x64** was the reference for the initial measurements. We subsequently repeated the Stoat ride on v0.18.0 with both the bare Garru and a Pack Beast wearing native luggage. The downstream examples are a skiff waiting at a data-authored anchorage and a saddle that fits an owned animal. Both run in an optional mod. The existing mod API already covers per-world systems, queued commands, deterministic hashing and sidecar saves. The animal accepts native move and stop orders. [Meitou's modding contract](https://github.com/VlcekM/MeitouClient/blob/v0.17.4/docs/modding.md) · [Transport simulation](../framework/TransportSystem.cs)

## Let test installations choose their terrain cache directory

Our live runner staged fresh installs with directory junctions to the same Kenshi data. The trial paths accounted for **549 derived terrain files, 3,170,713,824 bytes (2.95 GiB)**. In v0.17.4, a colour tile's key includes its source path, size, modification time and encoding version. The whole-world colour map also keys on source paths. Giving the same data another installation path therefore creates another set of keys. Repeatedly mounting an animal at one installation path does not exercise this mechanism. [Tile cache](https://github.com/VlcekM/MeitouClient/blob/v0.17.4/src/Meitou.Game/Rendering/Terrain/TerrainColourCache.cs) · [World colour cache](https://github.com/VlcekM/MeitouClient/blob/v0.17.4/src/Meitou.Game/Rendering/Terrain/TerrainTextures.cs)

Both cache implementations are byte-identical in the v0.17.4 and v0.18.0 tags. The existing runner uses `--no-load-cache` for disposable trials. To reproduce the storage issue, warm the same scene with caches enabled from two different test install paths pointing to the same data, then compare the derived terrain filenames. A second launch from the first path is the control. A small upstream change could honor an optional terrain cache directory for **both** tile and world colour output, like the existing object and impostor cache options. An acceptance test would check the default location, an alternate root, key invalidation after a tile changes, and the existing bypass. A directory override lets a tester choose storage and clean up the trial. Sharing keys between install aliases would require a separate invalidation design. [Downstream trial runner](../tests/LiveVoyage/run.ps1)

## Give mods a way to attach an object to an animated bone

The original saddle and the rider pelvis need the **same posed bone in the same rendered frame**. A simulation position alone misses the stride. Reading the latest simulation tick can also get ahead of the snapshot being drawn. The current adapter associates the transport state with the drawn snapshot, hooks the end of `CharacterRenderer.PoseLive`, reads the private live entries and bone matrices, places the rider's parts again, and submits the saddle via `CollectBolts`. It waits for the streamed animal rig before drawing the rider in the world. Growth scales the saddle and its offset while the rider retains their own proportions. An adult two-character run checked alignment in **124 posed frames** across idle, walk, run and a turn. The Stoat run checked the fitted rider through 140 posed frames over 11.4 units of elevation change, then saved, reloaded, remounted and switched to the Domesticated Bull. The separate Pack Bull author trial exercised a different fit on sloped terrain. [Recorded Stoat ride](https://streamable.com/5592xt) [Frame and mesh submission](../framework/Presentation.cs) · [Bone attachment adapter](../framework/MountedDrawing.cs) · [Live checks](../tests/LiveVoyage/LiveRide.cs)

Meitou v0.18.0 draws the Pack Beast's skinned luggage and offers custom inventory slots for humanoids. Our remaining use case is placing a second animated character on a named bone of the carrier in the frame being drawn. In the v0.18.0 Stoat Pack Beast trial, the saddle and rider each stayed within 0.009 world units of the authored attachment over 148 checked frames, including a 91.8-degree turn. [Animal appearance](https://github.com/VlcekM/MeitouClient/blob/v0.18.0/src/Meitou.Data/Characters/CharacterAppearance.cs#L842-L879) · [Equipment slots](https://github.com/VlcekM/MeitouClient/blob/v0.18.0/docs/modding.md#L134-L140)

An issue for maintainers could ask for the narrowest supported way to submit a loose mesh or place an already-rendered character relative to a named, posed bone for one frame. A useful acceptance scene has two moving actors, an animal that streams into view, and a turn. The rider, saddle, bounds and equipment should update together after the pose workers complete. The mod can keep ownership, seating rules and authored fits. A previous broader runtime-character proposal drew a different design preference from the maintainer. This is a reason to bring the working sample and ask about the intended interface before writing an upstream patch. ## Findings that stay with the playtest

- **Dismount drift and save projection.** The native movement step can still integrate the preceding velocity after orders are cleared. Transport releases ownership at a tick boundary, holds the chosen exit for that step and projects safe footing and filtered travel orders into the native save. Saving mid-ride must let the live trip continue. In the adult check, the animal stopped and the dismounted rider walked 20.8 units on a new order. A wider engine API for movement ownership or save projection would need another concrete consumer. [Movement and save adapter](../framework/TransportControls.cs) · [Ride regressions](../tests/RideChecks.cs)
- **A full-world Vulkan failure.** One RTX 3070 trial lost the device on `vkQueueSubmit` after warm-up, before boarding, with 2,504 of 7,249 MB reported in use. Other full-world trials completed. The cause remains open. A matching no-mod run on the same client, driver and scene would be useful before proposing a fix. Upstream issue 319 records a similar symptom on a different GPU and client build. [Upstream Vulkan report](https://github.com/VlcekM/MeitouClient/issues/319)
- **Stock luggage visibility.** The Pack Beast retained its equipment in v0.17.4. That renderer displayed the lantern alone. The v0.17.4 bags fixture drew the installed luggage for a clearance check. The production pack leaves native backpack rendering to Meitou. Upstream tracked the missing backpack separately. [Pack Beast backpack issue](https://github.com/VlcekM/MeitouClient/issues/581)

The optional live driver includes the independent-author Pack Bull, Western Hive save, and two-actor fit scenarios. Their setup lets a maintainer reproduce an individual observation without private logs, patched client binaries or a bundled game installation. [Scenario instructions](../tests/LiveVoyage/README.md)
